# Promo Picker – Kuku AI Generalist Assignment

**Problem 1: Find the Promos (Ads)**

## 1. About the Project

I chose Problem 1 because finding good promotional clips is an important part of attracting viewers to microdrama shows.

Currently, editors have to go through episodes and manually select interesting moments for ads. This can take time, especially when there are many episodes.

I built a small tool called **Promo Picker** to make this process easier.

The tool reads screenplay files and suggests 20–60-second clips that could work as promotional videos. It looks for moments with a strong opening, an interesting story and an ending that makes viewers curious about what happens next.

The goal is not to replace editors, but to help them find promising scenes faster.

## 2. What My Tool Does

- Reads screenplay TXT files or a ZIP containing multiple episodes.
- Finds possible promotional clips between 20 and 60 seconds.
- Shows the episode number and exact start and end timestamps.
- Gives each clip a score based on its hook, cliffhanger, clarity and emotional impact.
- Ranks the selected clips and explains why they may work.
- Allows an optional Gemini AI review of selected clips.
- Lets users download the results in CSV and JSON formats.

The application is built using Python and Streamlit.

## 3. How It Works

I divided the project into a few simple steps.

**Step 1: Read the scripts**

The program reads each episode and extracts the dialogue, actions and timestamps.

**Step 2: Find possible clips**

Using the timestamps, it creates possible 20–60-second clips. The start and end times are taken from the screenplay, not generated by AI.

**Step 3: Score the clips**

I used a simple scoring method with these weights:

| Factor | Weight |
|---|---|
| Opening hook | 30% |
| Cliffhanger | 30% |
| Story clarity | 25% |
| Emotional impact | 15% |

I chose these weights because a strong opening and an interesting ending are especially important for short promotional videos.

**Step 4: Rank the clips**

The tool ranks the candidates and removes some overlapping selections so that the results are not too repetitive.

**Step 5: Optional Gemini review**

I added Gemini to check whether the shortlisted clips are actually interesting and understandable to someone who has never watched the show.

Gemini gives feedback about the hook, ending and possible weaknesses.

I kept this step optional so that the project can still work without an API key.

## 4. Results

I tested the tool using the 50 screenplay files provided by Kuku.

| Result | Value |
|---|---|
| Episodes processed | 50 |
| Script events extracted | 3,727 |
| Candidate clips found | 299 |
| Final ranked suggestions | 20 |
| Clips reviewed using Gemini | 15 |
| Automated tests passed | 7 |

All 50 episodes were processed successfully.

I also compared the original rule-based results with the Gemini-reviewed results.

One observation was that some clips received high scores from the rule-based method even though their endings were not strong cliffhangers. Gemini helped identify some of these problems.

However, Gemini's scores are also subjective, so I would not directly assume that its recommendations will perform better as advertisements.

## 5. Problems I Found and Limitations

During testing, I noticed a few problems:

- Some emotional scenes received good scores even when the story was already resolved.
- Some clips started in the middle of a conversation, making them difficult for new viewers to understand.
- Different clips sometimes contained similar parts of the same scene.
- Gemini reviews did not always agree with the original scores.

I also found an issue when comparing Gemini-reviewed clips with clips that had not been reviewed. Their scores were not directly comparable, so I changed the application to display them separately.

Another limitation is that the tool only reads screenplay text. It cannot judge acting, expressions, background music or the actual video quality.

Currently, it also selects continuous clips rather than combining scenes from different episodes.

Because of these limitations, **a human editor should make the final decision**.

## 6. How This Could Help Kuku

The main benefit is that editors would not need to start searching for promo moments completely from scratch.

They could upload the screenplay, look at the suggested clips and decide which ones are worth reviewing.

For a larger number of shows, the same process could be repeated without changing the code, provided the scripts follow a similar timestamp format.

I also kept the rule-based filtering before the optional Gemini review. This means that an AI model only needs to check selected candidates instead of every line of every screenplay, which can help reduce API usage and cost.

To know whether this actually saves time, I would compare how long editors take to find usable promos with and without the tool.

## 7. How to Run the Project

**Requirements:** Python 3.10 or newer.

First, install the required libraries:

```bash
pip install -r requirements.txt
```

Start the Streamlit application:

```bash
streamlit run app.py
```

The application will open in your browser.

Upload the screenplay ZIP file to see the ranked promo suggestions.

To generate outputs directly without using Streamlit:

```bash
python run.py --input "path/to/scripts.zip" --out outputs
```

To use the optional Gemini review, set your `GEMINI_API_KEY` environment variable and run:

```bash
python run.py --input "path/to/scripts.zip" --out outputs --use-ai
```

The project works without Gemini as well.

## 8. Project Files

| File | Purpose |
|---|---|
| `app.py` | Streamlit application |
| `parser.py` | Reads and processes screenplay files |
| `finder.py` | Finds possible promo clips |
| `scoring.py` | Calculates the rule-based scores |
| `ai_rerank.py` | Optional Gemini review |
| `review_utils.py` | Handles reviewed and unreviewed results |
| `run.py` | Runs the complete process and saves outputs |
| `tests/` | Contains automated tests |
| `demo_input/` | Contains a fictional sample episode |

To run the tests:

```bash
python -m unittest discover -s tests -v
```

## 9. Sample Input and Data Privacy

The `demo_input/` folder contains a fictional screenplay that can be used to test the code.

To run it:

```bash
python run.py --input demo_input --out outputs
```

I have not included Kuku's original screenplay files because they are confidential.

The actual outputs generated from all 50 episodes are shared separately with the assignment reviewers.

API keys and other private files are also excluded from this repository.

## 10. Final Note

This project is a small working prototype, not a complete promo-editing system.

My main focus was to build something that works on real screenplay files, gives understandable results and can be tested on new inputs.

If I had more time, I would improve the selection of cliffhangers, explore clips combining multiple scenes and compare the recommendations with clips selected by actual editors.

I think the tool can be useful as a first step in reducing the manual effort involved in finding promo moments.
